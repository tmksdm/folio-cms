# PRODUCT.md — Минималистичная файловая CMS

Версия требований: 1.1 (Stage 00, проект для ревью; изменения ещё не приняты). Язык интерфейса: русский. Цель: собственная переносимая CMS для статического сайта со статьями, без БД и серверной части в production.

## Обязательное поведение
- Главная: наименование сайта, поле поиска, список заголовков опубликованных статей с датами, новая статья первой, пагинация по 20 заголовков (параметр конфигурации).
- Каждая статья: отдельный URL, заголовок, дата, полное содержимое, навигация на главную.
- Публичные URL статей строго вида `/YYMMDD` и `/YYMMDD-N` (N от 2), без `.html` и завершающего `/`. Первая статья даты без суффикса. Главная — URL корня сайта; в GitHub Pages project site допустим префикс `/repo`.
- Markdown с YAML frontmatter; поддержка обычного Markdown, заголовков, ссылок, списков, таблиц, блоков кода, изображений и альтернативного текста. HTML внутри Markdown по умолчанию не выполнять без отдельного анализа угроз.
- Поиск по заголовку и телу опубликованных статей в браузере, без внешнего поискового сервера. Не индексировать черновики, служебные страницы и изображения отдельно от статей.
- Черновики: `status: draft` не попадают ни в какую публичную часть сайта/индекса/карты страниц. `status: published` публикуются. Ручная дата публикации, без автоматического планировщика.
- Светлая и тёмная темы; по умолчанию системная, явный выбор запоминается, нет мигания неправильной темы.
- Адаптивный минималистичный дизайн; доступность с клавиатуры, читаемая типографика и достаточно контрастные элементы; без внешних шрифтов и обязательных клиентских фреймворков.
- Изображения хранятся в репозитории, относительные пути в Markdown надёжно разрешаются при сборке. Не требовать внешний CDN.
- GitHub Pages поддерживает пользовательский домен и project site с префиксом `/repo`; все ссылки, ассеты и поиск должны работать в обоих случаях.
- Резервирование: Git — основная история, переносимый ZIP-экспорт источников контента, медиа и публичной конфигурации; документированная и протестированная процедура восстановления. Никаких секретов и `node_modules` в экспорте.

## Явные границы MVP
Нет БД, серверной админки, авторизации на сайте, комментариев, регистрации, личных кабинетов, категорий/тегов, RSS, автоматической отложенной публикации, аналитики, стороннего API для поиска. Не добавлять функции без согласования.

## Критерии качества
- 100–1000 статей без архитектурных изменений; не загружать полные тексты всех статей при открытии главной.
- JS-отключён: главная, список, пагинация, чтение статей и навигация работают; поиск может требовать JS с понятным сообщением.
- Не публиковать черновики, токены и внутренние исходники в build-артефакте.
- Успешная сборка и автоматические проверки в CI, smoke-тест опубликованного сайта.
- Предсказуемые постоянные URL; удаление/редактирование других статей не меняет адрес существующей.

## Уточнения Stage 00 для ревью

Обязательные функции и строгие article URL сохранены. Предложения [ADR-0001](docs/decisions/0001-static-cms.md) не считаются принятыми требованиями до ревью:

- Slug является ID, фиксируется при создании draft; date фиксируется вместе с ним. Draft ID и удалённые ID не переиспользуются. Диапазон предлагается 2000–2099 из-за YY, вопрос открыт.
- CLI автоматически назначает ID; GitHub web creation использует явный slug и реестр в PR. Автоматического web назначения без CLI нет в MVP.
- Raw HTML в Markdown предлагается отклонять при build; HTML внутри fenced code отображается текстом.
- Черновики и их уникальные медиа отсутствуют во всём dist, а не только в списке/поиске. В public GitHub repo исходники drafts видны: status не обеспечивает секретность репозитория.
- Корень '/' или '/repo/' допускает слеш; article URLs по-прежнему строго без слеша/расширения. Pagination — статическая '/page/N', размер по умолчанию 20.
- ZIP включает контент, медиа, реестр, публичный config и manifest совместимого кода; требует независимого хранения и проверенного восстановления.

Риски совместимости и live gate: [Stage 00 research](docs/research/STAGE-00.md). Поиск по целым русским словам обязателен; частичные слова/морфология требуют проверки, произвольный fuzzy/substring не гарантируется.
