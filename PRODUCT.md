# Folio CMS

Собственная универсальная CMS для нескольких независимых сайтов. Единая русскоязычная админка на Cloudflare Workers; с телефона можно будет создавать сайты, писать Markdown-статьи, загружать изображения, сохранять черновики и публиковать материалы.

- `folio-cms` содержит только движок и админку. Каждый сайт — отдельный GitHub-репозиторий с публичной ссылкой `https://tmksdm.github.io/site-name`; для главной допускается перенаправление Pages на адрес со слешем.
- Адреса статей: `<base>/YYMMDD`, `<base>/YYMMDD-2`, `<base>/YYMMDD-3`, без `.html` и завершающего слеша. Совместимость требуется доказать на реальном GitHub Pages на этапе публикации.
- Вход в админку — собственный одноразовый email-код через Resend, Turnstile и защищённую cookie-сессию, только один серверно настроенный адрес. Cloudflare Access/Zero Trust не используются. GitHub не используется для входа.
- GitHub API вызывается только сервером; секреты не попадают в браузер или Git. Без традиционной БД контента, обязательных платных сервисов и готовой сторонней CMS.
- Повседневная работа владельца выполняется из админки, включая телефон, без ручных коммитов или настройки каждого сайта в GitHub. Публичный сайт получит минималистичный адаптивный дизайн, список статей, полнотекстовый поиск, пагинацию и светлую/тёмную темы; затем — backup и восстановление.

## Только Stage 01

Минимальная адаптивная админка: обзор, пустой список сайтов, сведения о подтверждённой сессии, выход с отзывом серверной сессии. Все маршруты админки защищены серверной сессией; публичны только вход и необходимые ресурсы/API авторизации. SQLite Durable Object для атомарных кодов/лимитов. Подготовка Worker, автоматические проверки и инструкция развёртывания без Zero Trust.

GitHub-интеграции, редактора, загрузки файлов и создания сайтов пока нет. Старые требования Stage 00 отменены новым заданием; документы старой ветки не задают текущую дорожную карту.

Приёмка: админка собирается для Worker и доступна только владельцу после настройки Resend, Turnstile и сессий. Локальные тесты не доказывают опубликованную защиту. После этапа — внешнее ревью; следующий этап только по явному одобрению.
