## Подтверждено на живом GitHub [П]

Сохранённые заголовки: `x-ratelimit-limit: 6000`, `remaining: 5992` (первичный лимит не исчерпан), `x-accepted-github-permissions: administration=write; repository_creation=write`. ## Причина `403` не установлена

Остаток первичного лимита (`5992` из `6000`) не исключает secondary rate limiting, abuse detection и других серверных ограничений GitHub: сообщение `Rate Limit Exceeded` их не различает. Достоверно установлено только эмпирическое правило: installation-токен этого приложения на этом аккаунте не создаёт репозиторий user-владельца, а user-токен `gh` создаёт. Чего не хватает: наличие и значение `retry-after`, `documentation_url`, `x-github-request-id`, полное тело ответа (в отчёте не сохранены), поведение при заведомо невалидном теле и после окна `x-ratelimit-reset`. Повторять создание репозиториев для диагностики сейчас не нужно; минимальные проверки — в `ARCHITECTURE.md`, раздел «Рекомендация: вариант A».

## Документация против наблюдения по `POST /user/repos`

Ревью ранее сообщило, что этот endpoint поддерживает user access tokens, но не installation access tokens. На 2026-10-13 документация GitHub говорит обратное [Д]:

- машиночитаемые данные страницы «Permissions required for GitHub Apps»: запись `{"slug":"create-a-repository-for-the-authenticated-user","verb":"post","requestPath":"/user/repos","access":"write","user-to-server":true,"server-to-server":true}`; `server-to-server: true` обозначает installation access token (для сравнения `GET /user/repos` там же: `server-to-server: false`).
- блок «Fine-grained access tokens for "Create a repository for the authenticated user"» перечисляет **GitHub App installation access tokens** и требует `Administration` (write) либо `Repository creation` (write).

Измерение этого не подтвердило: installation-токен получил `403` (причина не установлена), доступ к endpoint'у у него не доказан. Документация — контракт, а не наблюдение за API, поэтому рабочим считается измеренный путь — user-токен.

## Принадлежность репозитория: переработано

Текстовые признаки больше не считаются доказательством: владелец может изменить описание или тему вручную.

- Единственное доказательство — `folio.json` со `managedBy`, случайным `site` id и версией. Только он даёт право писать в репозиторий.
- Описание `Folio site: …` и тема `folio-site` — подсказки для человека и дешёвый фильтр списка, прав не дают.
- Репозиторий без `folio.json` (частичное создание или чужой репозиторий) автоматически не изменяется: интерфейс показывает «требует подтверждения», и только явное действие владельца разрешает записать ровно один файл `folio.json`. Подтверждение — параметр запроса, а не хранимое состояние, поэтому отдельная база не нужна.
- Существующие файлы не перезаписываются ни при каких условиях; имена `folio-cms` и `<owner>.github.io` не трогаются никогда.
- Альтернатива «создавать репозиторий из template-репозитория» рассмотрена и отклонена: постоянный публичный шаблон, замороженное содержимое и всё равно нужен второй шаг для уникального id.

## Адреса статей [И]

При записанном `.nojekyll` и статическом файле `261013.html` адрес `/261013` отдаёт `200`, `Content-Type: text/html; charset=utf-8`, без `Location`; в браузере адресная строка остаётся `…/261013` и страница отображается [И]. Каталог `YYMMDD/index.html` → `301`; файл без расширения → `application/octet-stream` и скачивание вместо показа (переход в браузере прерывается с `ERR_FAILED`); `_redirects` не применяется; несуществующий путь → `404` с телом из `404.html`. Jekyll-permalink даёт тот же `200`, но требует имён постов `YYYY-MM-DD-slug.md`. Подробные таблицы — в `ARCHITECTURE.md` и `STAGE02_STEP1_EVIDENCE.md`.

Требование владельца к адресам **выполнимо в точном виде** — без `.html`, без завершающего слеша и без перенаправления. Схема-кандидат — статический `YYMMDD.html` плюс `.nojekyll` [И]; адрес второго материала дня (`YYMMDD-2`) проверяется в Stage 03.

Измерения на своём пробном репозитории 2026-10-13 их подтвердили и добавили главное — запрос файла `YYMMDD.html` без расширения отдаёт `200 text/html` без перенаправления.
