## Проверка утверждения ревью о `POST /user/repos`

Ревью сообщило, что этот endpoint поддерживает user access tokens, но не installation access tokens. На 2026-10-13 документация GitHub говорит обратное, и это зафиксировано в плане с источниками:

- Машиночитаемые данные страницы «Permissions required for GitHub Apps»: запись `{"slug":"create-a-repository-for-the-authenticated-user","verb":"post","requestPath":"/user/repos","access":"write","user-to-server":true,"server-to-server":true}`. `server-to-server: true` обозначает installation access token (для сравнения `GET /user/repos` там же: `server-to-server: false`).
- Блок «Fine-grained access tokens for "Create a repository for the authenticated user"» на странице endpoint'а перечисляет **GitHub App installation access tokens** и требует `Administration` (write) либо `Repository creation` (write).

Документация — контракт, а не наблюдение за API, поэтому совместимость с личным аккаунтом `tmksdm` не объявляется доказанной: первым шагом реализации идёт предварительная проверка на живом аккаунте (создание одного пробного репозитория installation-токеном). Если она не пройдёт, план переключается на запасной вариант: installation-токен для управления, user access token только для создания репозитория.

## Выбранная авторизация и сравнение вариантов

Выбран вариант D — installation-токен для всех вызовов: он единственный даёт полную автоматизацию без обслуживания токенов (JWT ≤10 минут → токен на час, при промахе кэша выпускается новый), не требует хранимого состояния и оставляет три секрета (`GITHUB_APP_ID`, `GITHUB_APP_PRIVATE_KEY` в формате PKCS#8, `GITHUB_OWNER`).

| Вариант | Создание репозитория | Обновление токенов | Что придётся хранить |
|---|---|---|---|
| D. installation-токен (выбран) | по документации да, подтверждается живой проверкой | автоматическое | ничего |
| A. user-токен для создания + installation для остального | да | user-токен 8 ч, refresh-токен 6 мес с одноразовой ротацией | последний refresh-токен (в Durable Object) |
| B. user-токен для всех вызовов | да | то же | то же |
| C. fine-grained PAT | да | ручное (бессрочный PAT допустим, по умолчанию 30 дней) | один статичный секрет |

Варианты A и B требуют также `GITHUB_CLIENT_ID`/`GITHUB_CLIENT_SECRET` и разовой браузерной авторизации владельца; истечение user-токенов — включаемая опция приложения (её отключение убирает обновление, но оставляет долгоживущий секрет). Вариант C проще всего в коде, но это долгоживущий bearer-секрет и ручная замена при отзыве; покрывает ли выбор «All repositories» новые репозитории, документацией не подтверждено. Полное сравнение, права по каждому вызову, поведение при истечении и отзыве — в `ARCHITECTURE.md`.

Минимальные права приложения: `Administration` (write), `Pages` (write), `Contents` (write), `Metadata` (read); право `Workflows` не запрашивается, потому что `.github/workflows` Folio не трогает. Лимит installation-токена — 5 000 запросов в час; на Workers Free ограничивают также 50 подзапросов на запрос и 10 мс CPU (ожидание сети в CPU не считается).

## Принадлежность репозитория: переработано

Текстовые признаки больше не считаются доказательством: владелец может изменить описание или тему вручную.

- Единственное доказательство — `folio.json` со `managedBy`, случайным `site` id и версией. Только он даёт право писать в репозиторий.
- Описание `Folio site: …` и тема `folio-site` — подсказки для человека и дешёвый фильтр списка, прав не дают.
- Репозиторий без `folio.json` (частичное создание или чужой репозиторий) автоматически не изменяется: интерфейс показывает «требует подтверждения», и только явное действие владельца разрешает записать ровно один файл `folio.json`. Подтверждение — параметр запроса, а не хранимое состояние, поэтому отдельная база не нужна.
- Существующие файлы не перезаписываются ни при каких условиях; имена `folio-cms` и `<owner>.github.io` не трогаются никогда.
- Альтернатива «создавать репозиторий из template-репозитория» рассмотрена и отклонена: постоянный публичный шаблон, замороженное содержимое и всё равно нужен второй шаг для уникального id.
