# Архитектура

## Stage 01

Один Worker, обычные HTML/CSS/JavaScript, без клиентского фреймворка и БД. Интерфейс и CSS/JS включены в серверный bundle и выдаются тем же Worker после авторизации. Отдельного публичного Static Assets binding нет.

Браузер → Cloudflare Access (email-код, разрешённый адрес) → Worker → HTML/ресурсы/GET API. Worker через `jose` проверяет подпись RS256, доверенный issuer, audience приложения, обязательные claims, срок действия и точное совпадение email. Один email-заголовок не считается доказательством доступа.

`src/auth.js` — проверка доступа; `src/worker.js` — маршруты и заголовки; `src/ui.js` — интерфейс. `/`, `/sites`, `/settings`, `/assets/*`, `/api/session`, `/api/sites` проверяются одинаково. Изменяющих API нет. Нет конфигурации → 503; нет JWT → 401; неправильный JWT/email или ошибка ключей → 403. Ошибки не раскрывают токены и claims. Ответы не кэшируются, CSP запрещает внешние ресурсы и inline-код.

Настройки `ACCESS_TEAM_DOMAIN`, `ACCESS_AUD`, `ALLOWED_EMAIL` хранятся в Cloudflare; локально — в игнорируемом `.dev.vars`. JWT не сохраняется клиентским JavaScript. Подписание и OTP выполняет Cloudflare, собственных паролей и фиктивного входа нет. В production нет тестового режима или обхода авторизации.

`tests/preview-server.js` — только localhost-стенд с временным тестовым RSA-ключом и настоящей проверкой подписи. Он не проверяет Cloudflare и не включён в Worker. Production-ключи загружаются только с настроенного `https://<team>.cloudflareaccess.com/cdn-cgi/access/certs`; кешируются в памяти с обновлением.

## Следующие этапы

Сайты, Markdown и изображения будут храниться в отдельных GitHub-репозиториях. На Stage 02 выбрать серверный доступ GitHub API с возможностью создавать репозитории, минимальными правами и credentials в Worker secrets. В Stage 01 ни credentials, ни GitHub-вызовов нет. Не выбирать заранее токен с широкими правами.

Старая ветка `stage/00-design` и Git-история сохранены для справки. Её Astro/CLI/односайтовая архитектура отменена. Полезные ограничения нового задания сохранены: постоянные URL, отделение черновиков от опубликованного результата, проверка реального хостинга.
